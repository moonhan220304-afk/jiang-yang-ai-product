红楼梦宇宙：全站前端架构图

这不是 UI 效果图。它定义用户从首页如何选择进入方式、每一页负责讲什么、以及所有路径最后如何回到可反复阅读的内容单元。

首页不是“新手 / 老手”二选一

它是一张入口总台：今天只想读一点的人、想系统读全书的人、想查人物关系的人、想咬住一句诗的人、想进入争议的人，都能从第一屏各自出发。

所有入口最后都回到同一种阅读单元

每条内容必须能看到：原文位置、必要注释、关联人物/章节/诗句、不同解释与下一步。这样系统不会散成很多互不相通的小功能。

01 / 首页到底讲什么

首页只负责分流、续读和激发好奇，不承担完整知识讲解。

首页：阅读入口总台/
红楼梦宇宙　/　搜索　/　我的进度
人物章节诗句议题

首先回答：你今天想怎样进入？

不是“读完红楼梦”，先从一个让你想继续的入口开始。

若有阅读进度，优先显示“继续读：第 27 回 / 黛玉葬花”；若没有，则呈现五种可选入口。

继续上次阅读　→

A / 随手读

今天读一点给无目的打开的人。每天可变，5 分钟内读完。
今天这句“花谢花飞花满天”里，谁在看？

诗句 → 场景 → 忽略的细节

今天这人王熙凤第一次出场，为什么让人过目不忘？

人物 → 片段 → 关系入口

今天这事刘姥姥进大观园，笑话谁？

事件 → 原文 → 不同读法

B / 系统读

读一遍全书给愿意反复品读的人。保存进度，但不强迫线性完成。
按章回从第 1 回继续

120 回地图、当前进度、章节导读

按人物弧线跟着林黛玉读

她出现的章节、事件、问题

按主题从“大观园”读起

空间、诗社、婚姻、家族兴衰

C / 查与探

知道自己要找什么给有明确对象或问题的读者。
人物与关系金陵十二钗、贾府、四大家族

人物索引 → 关系图 → 人物页

诗句细读一句诗能带回哪一回？

诗句索引 → 逐句注释 → 前后文

争议议题大家究竟在争什么？

议题 → 证据 → 不同观点

02 / 用户从首页到内容的完整链路

实线是主要进入路径；虚线表示跨页跳转和保存进度后的回流。

03 / 每一页具体讲什么

开发时页面以这份职责表为准；没有独立用户问题的功能，不单独做成一页。

01 / HOME

首页入口总台

帮助用户选今天的阅读方式，并承接上次进度。

  • 继续上次阅读
  • “今天这句 / 这人 / 这事”横向卡片
  • 系统读、人物、诗句、议题四个长期入口
02 / READ MAP

系统阅读地图

解决“我想完整读，但不知道从哪开始、也不想被课程绑住”。

  • 120 回章节地图与进度
  • 人物弧线：跟着一个人读
  • 主题线：大观园、诗社、婚姻、家族等
03 / CHAPTER

章回阅读页

承载整本书阅读。不是只放原文，而是提供不打断阅读的定位和跳转。

  • 原文、回目、当前版本、章节导读
  • 本回人物、事件、诗句与伏笔
  • 上下回、相关主题、收藏进度
04 / CHARACTER

人物索引与人物页

解决“这个人是谁、和谁有关、为什么值得看”。

  • 分层浏览：核心 24 人 → 60–80 人底库
  • 关系图、出场章节、关键事件
  • 从具体问题进入，不只给生平标签
05 / POETRY

诗句细读页

解决“这句很好，但我以前漏看了什么”。

  • 原句、作者/说话者、场景与章回
  • 逐句注释、对照句、意象线索
  • 回到完整诗作和上下文
06 / TOPIC

议题与证据页

给熟读者一个能继续碰撞、又不失去材料边界的空间。

  • 问题陈述与证据层：原文/版本/研究/社区
  • 两种以上读法及其依据
  • 引用、回应、审核状态与关联章节
07 / SEARCH

全局搜索与关系图

解决“我知道关键词，但不确定它属于谁、哪一回”。

  • 人物、章节、诗句、地点、议题统一检索
  • 名字别称与同名消歧
  • 关系图只做查阅工具，不抢首页入口
08 / MY READING

我的阅读

让反复品读有痕迹，不把产品变成社交打卡。

  • 书签、阅读进度、已读章节
  • 收藏的人物/诗句/议题
  • 私人笔记；公开回应另走审核流程
09 / EDITORIAL

编辑与审核后台

不面向普通用户，但决定整个知识系统是否可信。

  • 来源、版本、原文定位与引用审核
  • 人物/关系去重和别称管理
  • 社区回应审核、修订记录与下线状态
所有内容页的共同规则

原文事实、版本材料、研究解释、社区观点必须分开存、分开标、分开显示；每一页都要能跳到关联人物、章节、诗句或议题。首页的横向卡片是“今天怎么选”的交互，不是把所有内容做成卡片瀑布流。
